# Media and Screenshots

## Existing visual assets

- `design/` contains approved UI showcase images used as design references. They are not captures of the currently running app.
- `assets/images/brand/` contains app and Android launcher artwork.
- `assets/images/shop-illustrations/` contains product empty-state and status illustrations.
- `assets/images/products/` contains product imagery used in the app.
- `assets/fonts/` contains bundled font files and their included license notices.

There are currently no verified live-app screenshots or animated demo recordings in the repository. Do not label a design board, mockup, or generated composite as a screenshot of the shipped app.

## Adding product captures

- Capture Android and iOS screens from a verified development or release build. Label each image with platform and app version when that context matters.
- Use synthetic shop, customer, phone, and transaction data. Remove notifications, account names, device identifiers, and other personal information.
- Keep original captures and any edited store-promo artwork distinguishable. Do not edit UI states in a way that suggests behavior the app does not have.
- Store approved captures under `assets/images/screenshots/` and link them from the README with descriptive alt text. Avoid adding large recordings when a small, focused capture communicates the feature.
- For an animated demo, record a real app interaction, keep it short and legible, and ensure the recorded motion represents current behavior. Respect the app's reduced-motion behavior where available.
- Keep source and attribution information for third-party media alongside the asset or in a nearby attribution note. Check the asset's license before redistribution.
